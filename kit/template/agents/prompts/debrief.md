# Role debrief - five questions at every overlord / overmind close-out

Answer these as the last thing before you stop (before `agents/bin/usage session`, if you run it), into
`agents/state/debriefs/<YYYY-MM-DD>-<role>-<first 8 of the session id>.md`; create the folder if it is not there.
`<role>` is `overlord` or `overmind`; headless runs (a tick, a dispatched overseer) and one-off job sessions skip this.
One to three sentences each, with the **why**; name the moment, the file, the message. "Nothing" is a fine answer when
true; a padded answer is worse than a short one. Nobody grades these: the overmind reads them at each review to change
the framework, not to score the session. Two debriefs naming the same friction, guess or unclear rule get an edit at
that review. Cost: one turn on a warm cache, a few cents.

1. **Spent.** What did this session actually spend its turns on, and how much of that was this role's job?
2. **Friction.** What would have made the job easier - a file, a tool, a rule, a different prompt?
3. **Guesses.** Where did you guess or assume instead of knowing? What would have told you?
4. **Rules.** Which instruction was unclear, contradicted another, or made you work around it?
5. **Successor.** What does the next session in this seat need that is not in the carry or the state files?

Commit the file with the session's other state.
